# B24 设计变更归档

[本次更新说明](CHANGELOG.md)

运行 `python design-archiver.py` 会打开小型控制窗口，并自动在 Chrome 新窗口中打开本机 HTML 页面；控制窗口中的“打开变更台账”按钮可再次打开页面。关闭控制窗口会关闭本次启动器打开的 Chrome 台账窗口并停止本地服务，不会关闭其他 Chrome 窗口。Windows 未安装 Chrome 时改用默认浏览器。终端模式可运行 `python design-archiver.py --no-ui`，直接打开默认浏览器，按 `Ctrl+C` 停止。

首次运行安装依赖：`python -m pip install -r requirements.txt`。复制 `config.example.yaml` 为 `config.yaml`，填写本机 B24 Excel 台账、按 2025-10-01 切换的两个审批表模板和资料源目录。`config.yaml` 包含业务路径，仅留在本机，不同步到 GitHub。PDF 流程需要 Windows 桌面版 Microsoft Word、Bluebeam Revu 20 eXtreme 和系统的“Microsoft Print to PDF”打印机。程序默认查找 Revu 20 标准安装目录；特殊安装路径可通过 `BLUEBEAM_SCRIPT_ENGINE` 指向 `ScriptEngine.exe`。默认成果位于本项目 `output/B24`，页面不显示路径设置；如本机已有 `local_settings.json`，继续使用其中保存的目录。也可通过 `CLOUDSTATION_ROOT` 或 `CLOUDSTATION_ROOT_WINDOWS` 覆盖群晖同步根路径。

页面显示台账中所有填写了“变更通知单编号”的 B24 记录。每条记录可查看匹配的资料目录、PDF 和 DOCX，再逐项生成审批表、复制完整资料目录和 PDF/DOCX 文件、压缩原资料目录、将审批表 DOCX 转为 PDF 后使用 Bluebeam ScriptEngine 合并 PDF，并按竖向 A4、自动旋转、仅缩小的设置打印 A4 版。可勾选多条批量操作，或将已生成的多个独立成果目录打成总 ZIP。

表格支持 2K 宽屏布局，变更内容中的“；”和“。”后换行。编号说明、变更内容、进展备注等较长文本可悬停或点击查看完整内容。各列筛选器位于表头下方；专业、面单状态、变更完成情况可下拉筛选，其他字段支持关键词筛选。顶部显示本地 AI 连接状态，并每 30 秒检查一次。

“批量进展备注”窗口左侧可手动输入一个或多个变更编号，右侧输入统一内容并追加到每条记录的汇总 JSON“人工备注”数组中。编号按台账精确校验；完成状态记录遵循单条备注的限制，无法追加时会在结果中列出编号和原因；新增备注可再通过顶部 AI 批量按钮统一判定。

归档页面采用暖白、青绿和薄荷绿的卡片风格。“变更完成情况”会显示绿色“已完成”、红色“未完成”、黄色“进行中”或人工标注的“作废”；已完成行显示绿色底纹，作废行显示白色底纹和贯穿斜线。状态可按表头筛选。新记录按单位勾选情况推断初始状态。追加的进展备注先写入汇总 JSON；点击顶部“AI批量更新变更情况”后，本地 AI 会分析有新备注的记录并生成状态和摘要，结果及更新时间写入汇总 JSON 并显示在页面中。每条记录也有“AI判定”按钮，可根据已有备注重新判定；AI 判为“进行中”时提供“人工设定”按钮，人工覆盖的状态与来源也保存在总表 JSON 中。每条记录可人工标注作废，已作废记录可恢复为其他状态。AI 不可用时备注仍会保存，可在服务恢复后再次点击批量按钮。未全部完成的记录可追加备注；内容及本地保存时间写入总表 JSON，历史备注不可覆盖，页面不显示保存时间。完成的记录不能新增备注。备注和 AI 标注不会写入单条变更文件夹的 `record.json`。

作废记录仍保留在表格中，但不会计入顶部的变更总数、当前显示数、成果目录数或专业筛选数量。

本地 AI 使用 OpenAI 兼容的 llama.cpp 服务。将 `common.env.example` 复制为本机 `common.env`，设置 `LLAMACPP_BASE_URL`、`LLAMACPP_MODEL`、`LLAMACPP_API_KEY` 和 `LLAMACPP_TIMEOUT_SEC`。`common.env` 已加入 Git 忽略列表，API Key 不应提交。默认地址为 `http://127.0.0.1:8080/v1`；同一台电脑上的服务若监听局域网 IP，也可将 `LLAMACPP_BASE_URL` 配为该私网地址。顶部状态显示服务健康检查结果。更换配置后重启归档程序。

表格中的变更通知单编号是链接，点击会在文件管理器中打开该条成果目录；目录尚不存在时会先创建。

页面的操作栏与表格标题行在滚动条目时保持可见，日期保持单行。页面根据“变更通知单编号”的前缀填写并筛选专业：`05` 给排水、`06` 暖通、`JZ-05` 精装给排水、`JZ-06` 精装暖通、`R20`/`RL20` 热力、`251614GC` 燃气、“泳池变更”泳池设备。原始台账字段仍供审批表模板替换使用。

启动、重读台账或复制资料时，程序会更新输出根目录下的 `B24变更条目.json`，并在每条变更文件夹内写入 `record.json`。原始资料直接放在对应变更文件夹中：源目录顶层的 PDF、Word 等文件直接位于该文件夹，`word&CAD` 等子目录也直接保留在该文件夹下，不再创建“原始资料目录”和“资料文件”两层包装目录。JSON 中的“资料文件”路径相对于本条变更文件夹。JSON 字段名会去掉台账表头中的中文数字标记；`_id` 是由变更通知单编号生成的稳定 SHA-256 hash，原编号继续用于页面显示、资料匹配和成果命名。

`input/` 中的多工作表 Excel 可通过本地脚本 `sync-processing-status.py` 读取。脚本在本地按 B 列“变更编号”与总表中的“变更通知单编号”精确匹配，将可识别的蓝图勾选状态以及工作表、行号、业主审批原值写入**根目录总表**的“处理情况”，不会写入各变更文件夹的 `record.json`。总包、监理、建设单位默认均为 `×`；Excel 中可读到的勾选会更新为 `√`。同一编号出现在多个 sheet 时保留每条来源；编号以 `JZ-` 开头且在“精装”工作表中也出现时，增加“精装表标记”。新建变更记录也会自动获得默认状态。`python sync-processing-status.py --ids 05-03-C2-001` 只预览，增加 `--apply` 才写入指定编号；全部处理使用 `--all --apply`。

`config.yaml` 中的 `legacy_config_files` 可引用 `AutoZipFolder/path_config_B24.yaml` 和 `CopyZipDesktop/path_config_B24.yaml`，程序会合并这两个项目配置中的资料、PDF 和 DOCX 来源并去重。页面点击“同步已有资料”会将匹配的文件夹及 PDF/DOCX 复制到每条变更的成果目录，自动更新 JSON；再次同步会跳过已复制且内容相同的文件。不存在的来源目录不会阻止其余资料复制。

示例配置中的 `legacy_config_files` 可按本机路径调整；这两个旧项目没有安装时也可以删掉该配置项，只使用 `source_directories`。更新程序后需重启本地服务，浏览器刷新页面即可使用新界面。若其他脚本读取旧 JSON，请注意 `_id` 已改为 hash，原编号仍在“变更通知单编号”字段。

每条变更使用输出根目录下的独立文件夹。单条合并可勾选要合并的 PDF；批量合并遇到多个候选 PDF 时会报告该条编号，留待人工选择。已有审批表和 ZIP 不自动覆盖；同名但内容不同的复制文件会追加序号；已有合并 PDF 需人工处理旧文件后才能重做。页面只在本机 `127.0.0.1` 运行。资料源目录不存在时会在预览中提示。

合并输出保留原 PDF 页面；A4 版通过 Revu 的 `PrintToFile` 调用“Microsoft Print to PDF”。本机 Bluebeam PDF 打印机在此命令下只生成 PostScript，因此不能直接作为 PDF 输出端。打印版可能不保留原 PDF 的可搜索文字和交互对象，需要检索时使用同目录的未重排合并版。

测试：`python -m unittest discover -s tests -v`。测试仅使用临时台账和临时资料，不写入真实业务目录。
